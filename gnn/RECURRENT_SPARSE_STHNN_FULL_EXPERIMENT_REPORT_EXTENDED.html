1. Data, Graph and Common Target Definition

All experiments are based on Cisco LOBSTER order book files with 10 levels. Each sample is transformed into a graph-like tensor where each node represents one side-level-lag combination, and each node has two features: price and volume.

node feature vector = [price_feature, volume_feature]

The target is a three-class future mid-price movement label:

0 = down
1 = flat
2 = up

The common target settings are:

price_type: mid
label_mode: abs
threshold: 100
prediction_horizon: 50

With these settings, the label is assigned from the future mid-price movement over 50 events:

down: future movement <= -100
flat: -100 < future movement < 100
up: future movement >= 100

Meaning of flat. The flat class means that the future movement is smaller than one tick in absolute value. In LOBSTER-style integer price units, a movement of 100 corresponds to one tick when prices are scaled by 10000. Therefore, flat is not a model component and not a graph edge: it is the neutral/no-direction label.

Graph Source

The graph used by RecurrentSparseSTHNN is obtained from the Cisco NMI-mean matrix:

csv_NMI_matrix/lob_similarity_nmi_rellag_lag150_bins2000_mean.csv

A TMFG is built from this matrix and exported as a labeled adjacency matrix. The recurrent model requires labels such as ASKs1_lag100 or BIDs10_lag0, so that it can identify both the feature identity and the lag index of every node.

Lag 100 adjacency:
data/adjacency/recurrent_sparse_tmfg_lag100_bins2000_from_nmi_mean.tsv
nodes = 2 sides * 10 levels * 101 lags = 2020

Lag 150 adjacency:
data/adjacency/recurrent_sparse_tmfg_lag150_bins2000_from_nmi_mean.tsv
nodes = 2 sides * 10 levels * 151 lags = 3020

2. Exact Model Used: RecurrentSparseSTHNN

The model is implemented in the project as an independent architecture:

gnn/src/models/recurrent_sparse_sthnn.py

The pipeline-facing class is RecurrentSparseSTHNNClassifier. Internally, it wraps a recurrent sparse core called BaseRecurrentSparseSTHNN.

2.1 Input Shape and Node Ordering

The processed dataset stores each sample as a static tensor:

[batch, num_nodes, 2]

where the last dimension contains the two node features: price and volume. The number of nodes depends on the lag setting:

lag100: num_nodes = 2 * 10 * (100 + 1) = 2020
lag150: num_nodes = 2 * 10 * (150 + 1) = 3020

The historical preprocessing order and the adjacency order are not assumed to be identical. For this reason, the classifier performs an explicit label-based reordering before passing the tensor to the recurrent core:

x_ordered = x_batch.index_select(1, node_reorder_idx)

This is important because the graph adjacency is labeled and ordered by recurrent labels, while the preprocessed LOB tensor follows the original project ordering.

2.2 Node Encoder

Each node starts with two features. These are mapped to a hidden vector by a small MLP:

Linear(2, hidden_dim)
ReLU
Linear(hidden_dim, hidden_dim)
ReLU

In all reported experiments:
hidden_dim = 5

2.3 Sparse Edge Blocks

The model does not use one independent parameter matrix for every single edge. Instead, it groups edges by an EdgeKey:

(target_feature, source_feature, lag_distance)

Each unique edge key has a learnable block matrix of shape:

[hidden_dim, hidden_dim]

These block matrices are stored in edge_blocks. During message passing, the source node hidden state is multiplied by the block assigned to that edge type.

edge_message = source_hidden @ edge_block

# Efficient implementation:
torch.einsum("bed,eod->beo", source_hidden, edge_blocks)

2.4 Temporal and Same-Lag Messages

The adjacency is converted into two main types of message edges:

  • Temporal edges: connect source and target features at different lags.
  • Same-lag edges: connect features within the same lag.

For temporal edges, the model identifies which node is at the more recent lag and which one is at the older lag. Messages are then created for all compatible lag positions using the same lag-distance block. This is the recurrent/shared-operator part of the architecture: the same learned block is reused whenever the feature pair and lag distance match.

Important: This is not a standard LSTM. It uses a GRUCell for hidden-state updates, but the temporal structure comes from sparse lag-distance operators defined by the TMFG adjacency. Equal feature/lag-distance patterns share the same operator.

2.5 Hidden-State Update

Messages from temporal edges, optional synthetic temporal edges, and same-lag edges are summed per target node. The model then updates each node hidden state with a GRU cell:

hidden_next = GRUCell(messages, hidden_previous)

message_iterations = 1

Therefore, each forward pass performs one full recurrent sparse message update before readout.

2.6 Readout

The readout mode used in all experiments is:

readout_mode = all_lags

This means that the hidden states of all nodes and all lags are flattened and passed to a final linear classifier:

flattened_hidden = hidden.reshape(batch_size, num_nodes * hidden_dim)
logits = Linear(num_nodes * hidden_dim, 3)(Dropout(flattened_hidden))

readout_dropout = 0.15

2.7 Main Configuration

model:
  type: recurrent_sparse_sthnn
  hidden_dim: 5
  message_iterations: 1
  readout_mode: all_lags
  readout_dropout: 0.15
  add_self_lag_edges: false
  out_dim: 3

3. Metrics: What They Mean Qualitatively

Metric Meaning
Accuracy Percentage of all samples classified correctly. Since flat dominates the dataset, high accuracy often means the model is good at recognizing flat periods, but it does not guarantee good directional prediction.
Macro F1 Average F1 over down, flat, and up with equal class weight. This is more informative than accuracy when classes are imbalanced, because down and up matter as much as flat.
Weighted F1 F1 averaged according to class frequency. Since flat is frequent, weighted F1 is strongly influenced by flat performance.
Signal Precision Among all predicted directional signals, how many are correct. Higher signal precision means fewer false trading-like signals.
Signal Recall Among all real down/up movements, how many are captured. Higher recall means the model misses fewer real movements, but it can come with more false positives.
Flat-to-Signal Fraction of true flat samples predicted as down or up. Lower is better if we want cleaner and more conservative directional predictions.

Precision vs recall in practice: Higher precision means that when the model predicts a movement, that signal is more reliable. Higher recall means the model detects more true movements, but it may also produce more false movement signals. In this project, lag100 tends to be more recall-oriented, while lag150 tends to be more precision/conservativeness-oriented.

4. Threshold Rules and Flat Penalization

The model itself always outputs logits, which are converted into probabilities:

P(down), P(flat), P(up)

The simplest decision rule is argmax, but argmax tends to produce too many directional predictions in this imbalanced setting. Therefore, we tune decision thresholds on the validation split:

if P(down) >= threshold_down: predict down
else if P(up) >= threshold_up: predict up
else: predict flat

4.1 Standard Threshold Tuning

score = macro_f1

This objective selects the threshold pair that maximizes validation macro F1.

4.2 Penalized Threshold Tuning

score = macro_f1 - 0.25 * flat_to_signal_rate

The penalization discourages threshold pairs that convert too many true flat samples into down/up predictions. It is used only during post-training threshold selection on the validation set.

Why this does not boost the model: The penalization does not update neural network weights, does not perform backpropagation, and does not expose test labels to the model. The trained checkpoint best.pt remains unchanged. Only the final decision thresholds are selected differently. Therefore, this is post-hoc calibration, not boosting.

train set -> learns model weights
validation set -> selects threshold_down and threshold_up
test set -> final evaluation only

The only methodological risk is over-tuning the decision rule if many different penalties/objectives are tried and the best one is selected based on test performance. For this reason, penalized results are reported separately from standard macro-F1 threshold results.

5. Bagging / Probability Ensemble

We tested a light bagging strategy by training the same model with different random seeds and averaging their predicted probabilities.

model_seed_42 -> probabilities
model_seed_123 -> probabilities
model_seed_777 -> probabilities
ensemble_probs = average(probabilities)

After averaging, thresholds are tuned on validation exactly as for a single model. This is not boosting: each model is trained independently, and no model is trained to focus on the previous model's errors.

5.1 Ensemble Variants Tested

Seed 42 + seed 123 + seed 777
Seed 42 + seed 123
Seed 42 + seed 123 with penalized thresholds

The ensemble did not produce a clear improvement over the best single model. Seed 777 was weaker, and including it reduced the ensemble's usefulness. The 42+123 ensemble matched the best macro F1, but it did not improve signal precision or flat-to-signal compared with the best single penalized model.

6. Split Strategies

6.1 by_lag

In by_lag, samples from all trading days can appear across train, validation, and test. This makes the evaluation less strict because the model can train and test on different samples coming from the same days. It is useful as an internal benchmark.

6.2 by_file

In by_file, full days are separated:

train: files [0, 1, 2]
val: file [3]
test: file [4]

This is a stricter day-held-out setting and is better for measuring whether the model generalizes to a new Cisco trading day.

9. Final Interpretation

Best internal performance: lag100 by_lag with penalized thresholds. Macro F1 = 0.6202, Accuracy = 0.8845, Signal Precision = 0.4432, Flat-to-Signal = 0.0696.

Most comparable result with the previous lag150 setup: lag150 by_file with standard thresholds. Macro F1 = 0.6009, Accuracy = 0.8639, Signal Precision = 0.4421, Flat-to-Signal = 0.0764.

Best lag150 result under by_lag: lag150 by_lag with penalized thresholds. Macro F1 = 0.6066, Accuracy = 0.8813, Signal Precision = 0.4304, Flat-to-Signal = 0.0697.

Overall, lag100 behaves more aggressively: it increases recall and macro F1, but it also increases false directional signals on true flat cases. Lag150 behaves more conservatively: it produces cleaner signals and lower flat-to-signal rates, making it more appropriate when comparability with the previous 150-lag model is required.

The ensemble experiments did not provide a clear improvement over the best single model. Therefore, the single-model configurations remain the most interpretable and defensible.

10. Extended Feature-Rich Walk-Forward Experiments

After those experiments, a new experimental block was added to make the evaluation stricter and the model input richer.

The new roadmap was:

Step 1: walk-forward / by-file evaluation
Step 2: feature engineering with book-derived and order-flow features
Step 3: weighted NMI/TMFG adjacency
Step 4: small hyperparameter grid
Step 5: stable thresholds across validation folds
Step 6: final seed ensemble on the best stable model family
Status: all six steps were completed.

11. New Model/Input Setup

The model family remains RecurrentSparseSTHNN. The architecture is still the recurrent sparse spatio-temporal graph model integrated as an independent model type. The final experiments use richer node features, weighted graph edges, and stricter walk-forward validation.

11.1 Feature-Rich Node Input

The original baseline used the preprocessed price/volume node representation. The feature-rich configuration extends each node with causal information computed only from the historical LOB window.

base features:
  price
  volume

book-derived features:
  spread
  level_imbalance
  depth_imbalance
  microprice
  side

order-flow features:
  order_trade_flow
  order_limit_flow
  order_cancel_flow

node_feature_dim = 10

The order-flow features are derived from the corresponding LOBSTER message files. They are historical/causal features attached to the same lagged window; they do not use future labels or future price movement.

11.2 Weighted NMI/TMFG Graph

The graph is still built from the Cisco NMI-mean matrix. The final weighted adjacency used by the best experiments is:

data/adjacency/recurrent_sparse_tmfg_lag100_bins2000_from_nmi_mean_weighted.tsv

The unweighted adjacency only tells the model whether two nodes are connected. The weighted adjacency also passes the edge strength from the NMI/TMFG matrix. In the model, edge weights multiply the message passed across each edge.

use_edge_weights: true
edge_weight_normalization: mean

This keeps the original sparse topology while giving stronger NMI/TMFG links more influence than weaker links.

11.3 Final Walk-Forward Split

The final evaluation uses expanding walk-forward folds over the five Cisco files:

fold_01:
  train = files [0, 1]
  val   = file  [2]
  test  = file  [3]

fold_02:
  train = files [0, 1, 2]
  val   = file  [3]
  test  = file  [4]

This is stricter than by_lag because validation and test are full unseen days. It is also more informative than a single by_file split because it measures the same model family across multiple chronological validation/test windows.

15. Step 6: Final Seed Ensemble

The final ensemble was designed to avoid temporal leakage. Models from different temporal folds were not directly mixed into the same test decision. Instead, each fold received its own seed ensemble.

fold_01 ensemble:
  base fold_01 checkpoint
  fold_01 seed123 checkpoint
  fold_01 seed777 checkpoint

fold_02 ensemble:
  base fold_02 checkpoint
  fold_02 seed123 checkpoint
  fold_02 seed777 checkpoint

For each fold, probabilities were averaged across the three members. Thresholds were tuned on that fold validation set and then averaged across folds to obtain stable ensemble thresholds.
